AI player analytics

CricLive groups every player into a player type using K-Means clustering, the same method as customer segmentation (RFM + K-Means). Instead of recency, frequency and spend, it uses cricket numbers: runs per match, strike rate, boundary %, wickets per match and balls bowled per match. The groups update automatically as new matches are scored.

How it works (step by step)
  1. Feature table: one row per player who has batted twice or bowled 2+ overs (from the player_stats table).
  2. Shrinkage: strike rate and boundary % are pulled towards a neutral value when a player has faced only a few balls, so one lucky hit does not mislead the model.
  3. Log transform (log1p) to reduce skew, then standard scaling (z-scores) so every feature counts equally.
  4. Elbow method: K-Means is run for k = 2 to 8 and the inertia is plotted. The bend in the curve suggests k = 4.
  5. Final model: K-Means with k = 4, k-means++ start, best of 10 seeded runs (repeatable results).
  6. Profiling: each cluster's average stats are compared and the cluster is named (Power Hitters, Anchor Batters, Strike Bowlers ...), with a coaching recommendation.
